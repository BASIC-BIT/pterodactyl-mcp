# Pterodactyl MCP development

This is reusable public source. Keep real panel addresses, private runtime
configuration, credentials and provider data in the operator's private deployment
repository. Use synthetic fixtures and preserve third-party license notices.

Use Node 24.22.1 or a newer Node 24 release. Run `npm run check` before reporting
a source change complete. Keep tests meaningful: actual SDK transport and
controlled-provider requests, independently asserted paths, inputs and effects.
Use failing regression tests before fixes. Live provider tests are separately
opt-in and require operator-owned disposable targets for mutations.

The operation catalogue owns route availability and input validation. Implemented,
excluded and pending states remain distinct. Do not count an identified route as
working functionality. `src/generated/provider-routes.json` is generated by
`npm run generate:routes` from the licensed pinned source under `spec/upstream`.
Run `npm run check:routes` after edits to either source or generated inventory.

STDIO stdout is reserved for MCP. Keep API families and configured origins
separate. No raw URL/path/credential proxy tools, disabled TLS verification or
automatic replay of ambiguous mutations. Use the maintained MCP SDK.

Consume the pinned shared quality-ratchet tool rather than copying its engine.
Public CI has no provider/deployment secrets and must never deploy the private
operator service. Repository publication, package publication and production
rollout are different actions; only perform the authorized action.
